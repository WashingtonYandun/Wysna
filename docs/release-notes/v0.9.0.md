# Wysna 0.9.0

Esta versión anterior a 1.0 consolida la arquitectura híbrida y amplía el contrato
estático que pueden consultar los agentes. La actualización desde 0.8 incluye
cambios de sintaxis y requiere regenerar manifiestos/locks de forma explícita.

## Cambios principales

- Anotaciones propias como metadatos tipados de esquemas `struct`, sin macros ni
  ejecución al compilar; `api`, `inspect` y `schema` las exponen. Se conservan
  `@deprecated` y `@must_use`, sus advertencias y la visibilidad de imports.
- Patrones alternativos, rangos Int64, structs anidados y W6003 para ramas ya
  cubiertas. W2003 añade familias pendientes en JSON. Se corrigen la identidad de
  patrones genéricos importados y el ocultamiento de globals por bindings locales.
- Catálogo único de versión, comandos por engine y guías `skills`, con generación
  nativa y verificación de frescura; no añade Python al runtime del SDK nativo.
- Tooling de proyectos, paquetes, MCP, LSP y schema en Selfhost; unidades dev con
  caché por contenido y bootstrap completo de tres etapas para integrar/distribuir.
- Paquetes USTAR fijados por SHA-256, restauración offline, pruebas congeladas,
  selección de casos por ID y protección contra planes obsoletos para agentes.
- Ubicación y pila de diagnóstico separadas por hilo. Los intrínsecos de async y
  paralelismo se reconocen por declaración/biblioteca, sin depender de números de línea.

## Migración obligatoria

Consulta [Migración 0.8 → 0.9](https://github.com/WashingtonYandun/Wysna/blob/{{SOURCE_COMMIT}}/docs/MIGRATING_0_8_TO_0_9.md).
Actualiza `package.language` a `0.9` y `toolchain.compiler` a `0.9.0` y ejecuta
`project lock` antes de usar `--frozen`. Usa `Class(...)`, `None`, `_ =>` y patrones
de tupla con paréntesis. Las capturas de closures permanecen inmutables.

## Distribución

SDK nativo con Zig incluido, sin Python para ejecutar `native-core-v1`:

- Windows x64: `wysna-0.9.0-native-x86_64-windows.zip`.
- macOS arm64: `wysna-0.9.0-native-aarch64-macos.tar.gz`.
- Linux x64: `wysna-0.9.0-native-x86_64-linux.tar.gz`.

Seed conserva Python como dependencia de implementación y se distribuye con
runtime privado en instaladores `.exe`, `.pkg`, `.deb` y `.rpm`. Los archivos
incluyen manifiestos, procedencia y `SHA256SUMS`. Los instaladores siguen sin firma
ni notarización; comprueba su procedencia y checksum antes de instalarlos.

## Límites del alcance

`int` conserva semántica Int64 y el ABI dinámico sigue siendo de 8 bytes. ARC
atómico no garantiza ausencia de carreras en todo el heap. El aislamiento de
workers, los grupos con cancelación, los anchos numéricos explícitos y nuevos
perfiles móviles siguen en [el plan del runtime](https://github.com/WashingtonYandun/Wysna/blob/{{SOURCE_COMMIT}}/docs/evolution/13-RUNTIME-AGENT-FIRST.md).
El backend estable sigue siendo C99; LLVM y el servidor experimental conservan
sus límites. Las mediciones con modelos reales continúan aplazadas.
